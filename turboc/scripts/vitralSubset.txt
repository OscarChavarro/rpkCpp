# Files of base/src/main that the RenderPark Turbo C++ port takes unchanged
# from VITRAL's own Turbo C++ port (turboc/base/src/main of a VITRAL checkout;
# plan D1: a pinned source subset). base/ holds exactly these files and nothing
# else: RenderPark's own classes live in rpkBase/.
# scripts/vitralSubset.sh --check compares each with a VITRAL checkout byte for
# byte and fails on any file of base/src/main missing from this list;
# --refresh copies them from it.
# Pin: VITRAL b3ab7058 (turboc/base/src/main). It holds, since cfd02831, the
# turboc counterpart of the double precision cpp commit: the Vector3Dd operations
# (lengthSquared, manhattanLength, distance, distanceSquared, multiplyByInverse,
# normalized, dominantAxis, component), Vector2Dd subtract and lengthSquared,
# Matrix2x2 on double / Vector2Dd, Vector3DPrinter for Vector3Dd, and KDTree,
# KDQuery, PlanarFace and the environment/material classes in double. This
# port is in double precision now: the single precision lineal algebra
# (Vector2Df, Vector3Df, Vector4Df, Matrix4x4f, Quaternionf) is still taken
# only because AlgebraPrimitives.cpp, which the primitives need, refers to it;
# no RenderPark class uses it.
# Added with the MGF reader on VITRAL primitives (cpp 27ad8ed8): the closure of
# environment/geometry/volume (Sphere, Cone, Tube, Torus, Prism and the
# PolyhedralBoundedSolid they are exported through, with its validation
# strategies and node printers), environment/geometry/element/Ray (which
# replaced RenderPark's RpkRay) and common/color/Cie (the immutable CIE color
# space that replaced RenderPark's static Cie).
# Added with cpp c2e31d2a: the convex polygon clipper of [SUTH1974b]
# (geometricProcessing/convexPolygonClipper) and the polygon scan converter and
# visibility buffer of [HECK1990] and [BEKA1997] (render/raster/polygonScanConverter)
# moved from rpkBase into VITRAL. PolygonScanConverter.cpp has no cpp
# counterpart: it defines PolygonScanConverterDepth::MAXIMUM_DEPTH, a static
# data member of the class template in the cpp port.
# Added with cpp 19b6fc7b and dda9386b (VITRAL's turboc port, uncommitted on
# top of the pin): CoordinateAxis and CoordinateSystem (common/linealAlgebra,
# their epsilon now a parameter) and io/PersistenceElement moved from rpkBase
# into VITRAL; the image persistence (io/image/ImagePersistence with
# ImagePersistenceRgbe, the media images and palettes it needs,
# RGBImageFloatUncompressed and java/io/BufferedOutputStream) replaced
# RenderPark's Dkcolor and image output handles.
# Files of the cpp port's subset left out of this port, although VITRAL's
# turboc port carries them: PlanarFace (plan step 3 part 2), the
# environment/material files of step 2a (Material.h, PhongLobe, PhongMaterial,
# ScatteringComponent, ScatteringFrame, SurfaceShadingPoint, Texture) and the
# thread support of parallel Jacobi (java/lang/Thread and Runnable): this port
# has not taken those steps yet (its Patch keeps its own face data, its
# materials are RenderPark's, its Galerkin refinement is serial). The cpp
# port's java/util/concurrent/locks/Condition.h, java/util/function/_LambdaHolder.h
# and GridSpatialIndex.txx (member templates) have no turboc counterpart.
