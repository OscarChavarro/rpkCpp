# Files of typescript/base/src/main that the TypeScript port takes from VITRAL's
# TypeScript port unchanged (plan D1: a pinned source subset). base/ holds
# exactly these files and nothing else: RenderPark's own classes live in
# rpkBase/. scripts/vitralSubset.sh --check compares each with a VITRAL checkout
# (its typescript/base/src/main) byte for byte and fails on any file of
# base/src/main missing from this list; --refresh copies them from it.
# Pin: VITRAL 789030e1 plus the TypeScript changes made for this split (the
# GeometryRay contract in its own module, so that Ray does not bring in
# Geometry; the scalar parameter code and the RayHit accessors of PlanarFace;
# the packed traversal arrays of BinnedSahHierarchy).
# The list is the Java-like layer (java/) and the closure, by imports, of the
# VITRAL classes RenderPark uses: the single precision lineal algebra
# (Vector2Df, Vector3Df, Vector4Df, Matrix4x4f, Matrix2x2), ColorRgb, Logger,
# PersistenceElement, RaytraceStatistics, PlanarFace, Ray, the spatial indexes
# with BinnedSahHierarchy, and the io/wrapper printers.
# Not here, although C++ takes them from VITRAL: java/io/File,
# FileInputStream and FileOutputStream (VITRAL keeps its Node file classes in
# the separate @vitral/fs package, with another API), java/lang/System (it
# needs FileOutputStream), MemoryPool and the io/wrapper pipe classes (VITRAL's
# TypeScript port does not have them). They are RenderPark's, in rpkBase/.
