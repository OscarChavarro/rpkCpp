# Files of typescript/base/src/main that the TypeScript port takes from VITRAL's
# TypeScript port unchanged (plan D1: a pinned source subset). base/ holds
# exactly these files and nothing else: RenderPark's own classes live in
# rpkBase/. scripts/vitralSubset.sh --check compares each with a VITRAL checkout
# (its typescript/base/src/main) byte for byte and fails on any file of
# base/src/main missing from this list; --refresh copies them from it.
# Pin: VITRAL f1b9d0a3 plus the TypeScript changes of this synchronization with
# VITRAL cpp 20e67173: double precision PlanarFace, PhongLobe, PhongMaterial,
# ScatteringFrame, SurfaceShadingPoint, Texture, KDTree/KDQuery, Matrix2x2 and
# the io/wrapper printers (no Math.fround); the new Vector3Dd (lengthSquared,
# manhattanLength, distance, distanceSquared, multiplyByInverse,
# normalized(epsilon), dominantAxis, component) and Vector2Dd (subtract,
# lengthSquared) methods; Ray setters (setOrigin, setDirection, setT,
# setOriginAndDirection), as in C++; and VITRAL 5c1a71c7 for the convex
# polygon clipper of [SUTH1974b] (geometricProcessing/convexPolygonClipper) and
# the polygon scan converter and visibility buffer of [HECK1990] and [BEKA1997]
# (render/raster/polygonScanConverter), which moved from rpkBase into VITRAL.
# Then VITRAL 95319652 (TypeScript port: migration from java advance seeking
# 1:1 parity), the Java to TypeScript alignment: Java exceptions
# (NullPointerException, IllegalArgumentException, IndexOutOfBoundsException)
# instead of TypeError/RangeError in the lineal algebra, Math.sqrt instead of
# Math.hypot in Vector2Dd/Vector4Dd lengths, the Java Double/Float parsing,
# the Matrix4x4d minor/determinant helpers, Containment values -1/0/1, the
# Cohen-Sutherland codes of ComputationalGeometry, Triangle closest point
# containment and the TriangleMesh vertex normals of the Java port.
# The list is the Java-like layer (java/) and the closure, by imports, of the
# VITRAL classes RenderPark uses: the double precision lineal algebra, ColorRgb,
# Cie, Logger, PersistenceElement, RaytraceStatistics, PlanarFace, Ray, the
# spatial indexes with BinnedSahHierarchy, the volume primitives the MGF reader
# builds patches from (Sphere, Cone, Torus, Tube, Prism) with the
# PolyhedralBoundedSolid kernel, and the io/wrapper printers.
# Not here, although C++ takes them from VITRAL: java/io/File,
# FileInputStream and FileOutputStream (VITRAL keeps its Node file classes in
# the separate @vitral/fs package, with another API), java/lang/System (it
# needs FileOutputStream), MemoryPool and the io/wrapper pipe classes (VITRAL's
# TypeScript port does not have them). They are RenderPark's, in rpkBase/.
